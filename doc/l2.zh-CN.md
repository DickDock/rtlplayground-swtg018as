# L2

[English](l2.md) | 简体中文

RTL827x 提供对一张 L2 表的访问与配置选项，该表用于把设备的 MAC 地址关联到局域网中能够到达这些设备的端口。目前的代码配置了自动学习（learning），并对所学地址的老化（aging）使用默认值。

## L2 表
对表的访问通过表访问寄存器完成。这些访问寄存器同时也提供对 VLAN 配置表的访问。关于该表的工作方式，可以从 [RTL8369 数据手册](http://realtek.info/pdf/rtl8366_8369_datasheet_1-1.pdf) 的第 8.17 节，尤其是其中的表 20 得到一个大致了解。

核心的表寄存器是 RTL837X_TBL_CTRL（0x5cac）。

```
Register RTL837X_TBL_CTRL bytes: EE EE TT CC
EE: Entry
TT: Table type
CC: Command (Bit 0: Execute, Bit 1: Write)
TT: 04: TBL_L2_UNICAST, 03: TBL_VLAN
```
从表中取出表项的方法是：先把数据输入寄存器设置为期望的表项过滤条件，然后向 RTL837X_TBL_CTRL 写入以执行表命令——置起执行位（bit 0）、设置表类型，并给出表项标识符（VLAN-Id，对 L2 则是哈希值）。数据随后会从表中取出，并在 ASIC 清除执行位之后即可使用。此时数据位于输出数据寄存器中：

```
#define RTL837x_L2_DATA_OUT_A	0x5ccc
#define RTL837x_L2_DATA_OUT_B	0x5cd0
#define RTL837x_L2_DATA_OUT_C	0x5cd4

DATA_OUT_A   DATA_OUT_B   L2_DATA_OUT_C
M2 M3 M4 M5  fV VV M0 M1  xx xF xx gg

M0-M5: 6 bytes of MAC, M0 is MSB
V: 12 bits of VLAN-ID
f: bit 5 set: Entry is valid, otherwise stale
   bit 6: bit 0 of port-number
   bit 7: bit 1 of port-number
g: bit 0: bit 2 of port-number
   bit 1: bit 3 of port-number (MSB)
   bit 2: bit 0 of entry-age
   bit 3: bit 1 of entry-age
   bit 4: bit 2 of entry-age (MSB)
F: bit 0: entry is static(1) or learned (0)
```
下一个表项的编号可以从 RTL837x_TBL_DATA_0 中得到（entry = RTL837x_TBL_DATA_0_bits（0-11） + 1）。把该值写入 RTL837X_TBL_CTRL，并针对给定的表类型再次执行，即可取得下一个表项。这个表项编号很可能是一个哈希值，其算法尚不清楚。

删除整个 L2 表的方法是：检查并把 0x53dc 设置为 0x0，然后向寄存器 RTL837x_L2_TBL_CTRL 写入 0x00010000，并等待被置起的 bit 16 被清除。


## 代码中的 API 支持
RTLPlayground 代码提供从 ASIC 读取 L2 表以及清空表（从而快速遗忘所学表项）的支持。

```

```

## 静态组播表项

LACPDU、STP BPDU 之类的慢协议（slow-protocol）帧必须到达 CPU，而不能被泛洪到其他端口。没有网桥会中继这些帧：它们的地址属于 802.1D-2004 第 7.12.6 条禁止网桥转发的地址集合，在网络上传送的是信息本身，每个网桥都会在自己的指定端口上重新生成属于自己的 BPDU。保留组播（reserved-multicast）的 *trap* 动作在这款硬件上做不到这一点，因为它的目的地是挂接在某个物理端口上的外部 CPU，而这些板卡并没有在该端口上连接这样的 CPU。因此，协议模块把保留组播动作保持在 *forward*，改为用一个静态 L2 组播表项来约束出方向（egress）：查找命中的是该表项自身的端口掩码，而不是 VLAN 泛洪掩码。已在 SWTGW218AS 上按两种方式验证：清除 CPU 位后，投递停止；仅保留 CPU 位时，则没有任何帧发出。

`port_l2mc_set()` 写入的就是这样一个表项。其 SMI 布局是该表项的 L2 组播变体：

```
DATA_IN_A = MAC bytes 5..2                            -> c2 00 00 <mac_last>
DATA_IN_B = MAC[1..0] | vid<<16 | IVL<<29 | pmask[1:0]<<30
DATA_IN_C = pmask[9:2]
```

查找采用 IVL 方式，因此为 VID 0 创建的表项永远不会被匹配到，调用方需要为每个在用的 PVID 各添加一个表项。写入通过表访问寄存器完成，表选择器设为 L2 查找表，在代码中名为 `TBL_L2_UNICAST`——这个名字虽然看起来只与单播有关，实际上同样覆盖组播表项。硬件会自行对 MAC 和 VID 做哈希来选择桶槽位。再次写入相同的 MAC 和 VID 会替换原表项而不是新增一个，因此调用方可以随时改写掩码，例如改回所有端口以恢复泛洪。
